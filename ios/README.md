# Poku Expenses (iOS)

SwiftUI + SwiftData + CloudKit port of the expense tracker. iPhone only, iOS 17+.
No third-party packages.

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml` and is git-ignored. Never edit or commit `PokuExpenses.xcodeproj`:
add files to the folders and generate again.

## Generate

```sh
brew install xcodegen            # once
cd ios && xcodegen generate
open PokuExpenses.xcodeproj
```

## Run

In Xcode pick the `PokuExpenses` scheme and an iPhone simulator, then Run (⌘R).
From the terminal:

```sh
cd ios && xcodegen generate
xcodebuild build -project PokuExpenses.xcodeproj -scheme PokuExpenses \
  -destination "platform=iOS Simulator,name=iPhone 17"
```

Without a development team the app still runs in the simulator. iCloud does not sync
there; data stays on the device and Settings shows the sync status.

## Test

```sh
./ios/scripts/test.sh                           # unit tests (scheme PokuExpenses)
./ios/scripts/test.sh PokuExpensesUI            # UI smoke tests (in-memory store, -uiTesting)
IOS_SIM="iPhone 17 Pro" ./ios/scripts/test.sh   # another simulator
```

The script uses `-quiet`: exit code 0 means green. For per-test output run the
`xcodebuild test` line from the script without `-quiet`.

The import tests read `PokuExpensesTests/Fixtures/web-export-v1.json`. The web test
`src/lib/export.utils.test.ts` checks that `buildExportFile` produces the same JSON, so
change both together.

## App icon

```sh
swift ios/scripts/make-icon.swift
```

Writes `PokuExpenses/Resources/Assets.xcassets/AppIcon.appiconset/icon-1024.png`
(single size, opaque). Commit the PNG.

## iCloud on a real iPhone

Sync uses the private CloudKit database in `iCloud.day.poku.myday`. It needs a paid
Apple developer account:

1. Xcode → Settings → Accounts: add your Apple ID.
2. Select the `PokuExpenses` target → Signing & Capabilities → choose your Team.
   Keep "Automatically manage signing" on. Xcode registers the bundle id
   `day.poku.myday` and the iCloud container. If either name is taken, change
   `PRODUCT_BUNDLE_IDENTIFIER` and the container in `project.yml` (and
   `AppContainer.cloudContainerID`) to your own.
3. The team you pick in Xcode is lost on the next `xcodegen generate`. To keep it,
   add `DEVELOPMENT_TEAM: <your team id>` under the app target's `settings` in your
   local copy of `project.yml`. Do not commit it.
4. Sign in to iCloud on the phone, then run on the device.

Records sync to the development CloudKit environment. Before shipping, deploy the
schema to production in the CloudKit Console.

## Bringing data from the web app

On the web: Settings → Your data → Export my data. On the iPhone: Settings →
Import from web, then choose that file. Importing the same file again adds nothing.
